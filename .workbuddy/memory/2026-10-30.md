## 第三批交付：Neon 瞬时连接故障韧性（晚间）

用户日志暴露：`GET /api/stats 500` —— `Error connecting to database: TypeError: fetch failed`（cause AggregateError/ETIMEDOUT），同一端点重试即 200，属连接抖动而非查询错误。

- 新增 `src/lib/db-retry.ts`：`isTransientDbError`（沿 cause 链识别 ETIMEDOUT/ECONNRESET/… 与 'fetch failed'，但 ENOTFOUND/证书类判定为不可重试）+ `withDbRetry`（指数退避，默认 2 次，可用 `DB_RETRY_ATTEMPTS`/`DB_RETRY_BASE_DELAY_MS` 调整）+ `describeDbError`（优先暴露根因而非 Drizzle 的 'Failed query' 外层包装）。
- 新增 `src/lib/db-read.ts`：`withStaleFallback`——查询成功写缓存，失败回退「上一次成功结果」的陈旧快照（响应头 `X-Cache: STALE`），空结果不缓存（保留 404 语义）。
- `src/lib/cache.ts`：新增 staleStore（15 分钟）与 `getStaleCache`/`expireFreshEntries`（测试钩子），失效时新鲜缓存与陈旧快照一起清。
- 接入 7 个读端点：stats / notes / notes[id] / segments[id] / graph / learning-today / learning-weekly；写路径一律不重试。
- 前端：`/notes`、`/progress`、首页概览在 503 时展示 `ErrorState`（原因 + 重试按钮 + 去向），不再是一行红字。
- 实测演练：生产构建 + 不可达数据库 → 7 个端点全部返回 503 `{"error":"数据库暂时不可用，请稍后重试"}`；用「localhost:5499」制造真实 ECONNREFUSED 时，日志出现 `[db-retry] stats.* 第 1 次失败`，总耗时 0.87s（含 2 轮退避）；健康路径（真实 Neon）全部 200 无回归。
- 关键认知：Neon HTTP 驱动把 `127.0.0.1` 改写成 `api.0.0.1` 导致 URL 解析错误（属不可重试），演练时要用 `localhost` 才能造出真实连接拒绝；undici 的错误形态为 `TypeError: fetch failed` + cause `ECONNREFUSED`/`ETIMEDOUT`。
- 验证：npm test 35 文件通过（新增 3 文件 17 用例）、typecheck / lint / build 通过。
