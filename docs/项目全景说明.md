## 1. 项目定位与目标用户

### 1.1 一句话用途

**个人知识库**：把 Markdown 笔记导入后自动拆成「知识点」并建立双链关联，以「记忆程度」为轴组织阅读、主动回忆、复盘与关系图谱的**单用户 Web 应用**。目标不是做通用笔记软件，而是回答「现在该读什么、哪些快忘了、学过的是否真的会了」。

| 项 | 内容 |
|---|---|
| 名称 / 版本 | `knowledge-base` v0.1.0（private，`package.json`） |
| 形态 | 单用户 Web 应用，单口令登录，无注册、无多租户、无公开分享 |
| 目标用户 | 单个学习者（作者本人）；自托管 / 个人部署 |
| 部署 | Vercel Hobby（个人非商业）；进程内缓存按单实例假设设计 |
| 工作语言 | 界面、代码注释、文档均为简体中文 |
| 本地启动 | `npm run dev` → `http://localhost:3000`（需 `.env.local` 中 `DATABASE_URL`、`AUTH_PASSCODE`） |

### 1.2 核心使用闭环

```
导入 Markdown  →  自动拆段 / 提标签 / 建双链  →  首页「今日学习」推荐
      ↑                                              ↓
  图谱看结构  ←  复盘看趋势  ←  主动回忆自测  ←  阅读知识点（停留时长驱动记忆度）
```

- **阅读即学习**：打开知识点计一次查看，停留达到阈值后推进稳定度；记忆度按 `exp(-Δt/S)` 读取时现算，不落库。
- **忘得快的地方在图谱里变暗**：节点亮度 = 记忆度，档位为 未读 / 微光 / 明亮 / 长明。
- **看过 ≠ 会了**：主动回忆先作答、再揭晓参考答案，三档自评分别对应 1 / 3 / 7 天后复习。

### 1.3 明确非目标

| 非目标 | 说明 |
|---|---|
| 多用户 / 注册 / 协作 / 分享 | 单口令会话，无权限体系 |
| 移动原生 App | 只做响应式 Web（含 PWA manifest 与安全区适配） |
| 富文本 / 图片为主的笔记 | 当前只支持 Markdown 纯文本导入 |
| 通用聊天机器人 | 助手对话只服务本库内容与本库学习进度 |
| 向量检索 | 当前检索为关键词 + 片段抽取，无向量库、无 tiktoken |

### 2.2 环境变量（以 `.env.example` 实值为准）

| 变量 | 必填 | 说明 |
|---|---|---|
| `DATABASE_URL` | 是 | Neon Pooled 连接串 |
| `AUTH_PASSCODE` | 是 | 登录口令；未配置时全站不可用 |
| `SETTINGS_ENCRYPTION_KEY` | 否 | LLM Key 加密主密钥；不填则由 `AUTH_PASSCODE` 派生（**改口令会使旧密文失效**） |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` | 否 | 不配则导入不备份原文，功能不受影响 |
| `LLM_API_KEY` / `LLM_MODEL`、`DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | 否 | 应用内「设置」页配置的回退；推荐用设置页（即存即用、无需重启） |

本地 `.env.local` 的值不写入任何文档；交接包同样只出现变量名。

### 2.3 运行时架构

```text
浏览器（Cookie 会话，HttpOnly）
   │
   ▼
src/proxy.ts                 全站登录门：/login、/api/auth 放行；
   │                        未登录页面 → /login?next=…；API → 401
   ▼
App Router 页面（RSC + 客户端组件）  ⇄  /api/* Route Handlers
   │                                        │
   ▼                                        ▼
src/components/*（展示与交互）      src/lib/*（业务层）
                                          │
                        ┌─────────────────┼──────────────────┐
                        ▼                 ▼                  ▼
                  Neon Postgres      Cloudflare R2      DeepSeek API
                  （唯一持久源）     （原文备份，可选）  （OpenAI 兼容，可选）
```

要点：

- 业务逻辑集中在 `src/lib/*`，路由只做鉴权、校验与编排。
- 数据库连接惰性初始化（`src/db/index.ts` Proxy），使 `next build` 导入路由模块时不立即连接。
- 多表写入走 Neon HTTP batch（`src/lib/db-batch.ts`），失败整体回滚。
- 读路径韧性：`src/lib/db-retry.ts` 瞬时故障重试 → `src/lib/db-read.ts` 回退陈旧快照（响应头 `X-Cache: STALE`）→ 完全不可用返回 503 + 页面重试入口。
- 两层缓存：进程内 TTL（`src/lib/cache.ts`）+ 数据库 LLM 输出缓存（`llm_cache` 表）。
- 会话过期的统一恢复：`src/lib/client.ts` 识别 401 后跳转登录页并带回原路径（登录页与认证接口除外）；2026-11 修复批次已把该能力从各页面收敛到请求层。

## 3. 安装与运行

```bash
npm install
copy .env.example .env.local     # Windows；Linux/macOS 用 cp；填 DATABASE_URL、AUTH_PASSCODE
npm run db:migrate               # 顺序执行 src/db/migrations/*.sql
npm run db:migrate:check         # 只读检查待执行迁移（--dry-run）
npm run dev                      # http://localhost:3000
```

### 3.1 脚本全表（`package.json` 实值）

| 命令 | 实际执行 | 用途 |
|---|---|---|
| `npm run dev` | `next dev` | 开发服务器（Turbopack） |
| `npm run build` | `next build` | 生产构建（需 `DATABASE_URL`） |
| `npm run start` | `next start` | 启动生产构建 |
| `npm run lint` / `npm run typecheck` | `eslint` / `tsc --noEmit` | 静态检查 |
| `npm run test` / `npm run test:watch` | `vitest run` / `vitest` | 单元与组件测试 |
| `npm run test:e2e` | `node scripts/run-e2e.mjs` | Playwright 回归（自动起 3100 端口 dev server） |
| `npm run perf:graph` | `node scripts/measure-graph.mjs` | 图谱性能测量 |
| `npm run db:generate` / `db:push` / `db:studio` | `drizzle-kit …` | 迁移生成 / 推 schema / 数据浏览 |

1. Vercel 导入仓库，配置 `DATABASE_URL`、`AUTH_PASSCODE`（可选 `SETTINGS_ENCRYPTION_KEY`、`R2_*`）；
2. 首次部署后手工执行一次 `npm run db:migrate`；
3. 已知平台限制：请求体上限约 4.5MB；多实例下进程内缓存失效为 best-effort；`public/fixtures/*.json` 被 `.gitignore` 忽略，新环境需重新生成。

### 5.2 核心交互流程

| 流程 | 入口 | 关键路径 |
|---|---|---|
| 导入 | `POST /api/notes` | `splitter.splitMarkdown` 按标题拆段 → 可选 `semanticSplit` → 写 `documents`/`segments` → 重建 wiki/tag/doc 边 → 可选 R2 原文备份 |
| 阅读即学习 | `POST /api/segments/[id]/view` | 打开 ping 记 `viewCount`；停留达阈值写 `reading_events` 并推进 `stability`；记忆度读取时现算 |
| 今日学习与自测 | `GET /api/learning/today` → `POST /api/learning/question` → `POST /api/learning/reviews` | 确定性推荐排序 → 生成问题 → `submissionId` 幂等提交自评并算 `nextReviewAt` |
| 图谱 | `GET /api/graph` 或 `/fixtures/<name>.json` | 节点 = 知识点；单击详情、双击阅读、Ctrl/Cmd+K 搜索、双选最短路径、学习地图标记、主题偏好持久化 |
| 助手 | `POST /api/ai/ask`（SSE） | 常驻知识库概览 + 学习者画像 → 工具 `search_knowledge`/`read_segment`/`propose_actions` → 改动**只提议不写库**，由前端确认卡走 apply |
| AI 改写 | `*-preview` → `*-apply` | 拆解 / 聚合两步确认；预览端点无业务写操作 |
| 认证 | `POST /api/auth/login` / `logout` | 口令校验 + HttpOnly Cookie；`src/proxy.ts` 全站拦截；401 由 `src/lib/client.ts` 统一跳登录 |

### 6.1 数据来源

### 6.2 数据模型（`src/db/schema.ts`，9 张表）

## 7. 约定与铁律

1. **零新增依赖优先**：新增依赖需先决策。
2. **LLM 输出永不直接写库**：一律 `preview` → 用户确认 → `apply`；助手 `propose_actions` 只提议。
3. **隐私最小化**：`llm_calls` 不记 prompt；设置页不回 API Key 明文（只回 `keyTail`）。
4. **记忆度读取时现算、不落库**：落库只有 `stability`、`readingMs`、`reading_events`。
5. **单用户、Key 只在服务端**：无注册、无多租户。
6. **写操作原子性**：导入 / 段编辑移动删除 / AI 拆解聚合均用 Neon batch 事务。
7. **文案与视觉语言**：界面中文；记忆档位用灯光隐喻，不用数字直出。
8. **Next 16 版本纪律**：改代码前读 `node_modules/next/dist/docs/`。
9. **文档纪律**：代码与文档冲突时以代码为准并回写文档；相对链接、命名与格式规范见 [README.md](./README.md) §2–§3。

## 8. 已知坑点与限制

| # | 坑点 | 影响 / 规避 |
|---|---|---|
| 1 | `next build` 需要 `DATABASE_URL` | 构建机无变量会失败；惰性 Proxy 只解决「无查询不连接」 |
| 2 | 进程内缓存多实例不一致 | Vercel 多实例时写后失效只作用于当前实例；个人自用 best-effort |
| 3 | 流式超时 | 整流超时 + chunk 静默超时，长回答可能被掐断（`src/lib/llm.ts`、`stream-utils.ts`） |
| 4 | Key 加密依赖口令 | 未设 `SETTINGS_ENCRYPTION_KEY` 时由 `AUTH_PASSCODE` 派生，改口令使旧密文失效；设置页据 `keyState` 提示重新填写（`src/lib/app-settings.ts`） |
| 5 | 图谱全量返回 | `/api/graph` 无分页 / 聚合；大图需单独排期（见 `plans/frontend-quality-audit.md` FE-002） |
| 6 | fixture 不入库 | 新克隆需 `node scripts/gen-graph-data.mjs` 生成 |
| 7 | Vercel 请求体 4.5MB | 超大 md 需分次导入 |
| 8 | 单用户认证强度 | 会话令牌由口令派生，泄露面等价于口令本身（设计取舍） |
| 9 | 标注可能失效 | 段改写后三级锚点重定位仍可能丢锚点 |
| 10 | 数据库抖动 | 读路径重试 → 陈旧快照 → 503 + 重试按钮 |
| 11 | 只支持 Markdown 纯文本 | 图片 / PDF / DOCX 未实现 |
| 12 | 文档可能滞后于代码 | 工作区含未提交改动；以代码与最新审计报告为准 |
