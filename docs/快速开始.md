## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | `v22.x`（本机实测 `v22.20.0`） | `db:migrate` 使用 `node --env-file=`，需 Node ≥20 |
| npm | 随 Node 附带 | 仓库有 `package-lock.json`，用 `npm install` |
| 数据库 | Neon Serverless Postgres（免费层即可） | 连接串必须是 **Pooled** 形式，带 `?sslmode=require` |
| 对象存储 | Cloudflare R2（可选） | 不配置也能正常导入，仅不备份原文 |
| 大模型 | DeepSeek（可选） | 推荐在应用内「设置」页填 Key；环境变量仅作回退 |
| 浏览器 | Chrome / Edge 现代浏览器 | 图谱使用 Canvas（`react-force-graph-2d`） |

## 2. 五步跑起来

### 2.1 安装依赖

```bash
npm install
```

### 2.2 准备环境变量

```bash
# Windows
copy .env.example .env.local
# macOS / Linux
cp .env.example .env.local
```

最少填两项（完整说明见 [配置说明.md](./配置说明.md)）：

```ini
DATABASE_URL=postgresql://user:pass@ep-xxx-pooler.xx.aws.neon.tech/neondb?sslmode=require
AUTH_PASSCODE=一段足够长的随机字符串
```

### 2.3 建表

```bash
npm run db:migrate         # 顺序执行 src/db/migrations/ 下的 SQL
npm run db:migrate:check   # 只读检查，不写库（--dry-run）
```

- 迁移执行器：`scripts/apply-migrations.mjs`，用 `_kb_migrations` 表记录已执行版本。
- 重复执行不会重放历史迁移；对「已有完整表结构但无版本表」的旧库会自动建立基线。
- 当前迁移文件 8 个：`0000_init` → `0007_wooden_wong`。

### 2.4 启动

```bash
npm run dev
# 打开 http://localhost:3000
```

> **重要**：在 Windows 上如果浏览器一直停在骨架屏、页面不水合，请改用
> `npm run dev -- --hostname 127.0.0.1 --port 3300`。原因见 [常见问题排查.md](./常见问题排查.md) §1。
> 另外 Next 16 单项目只允许一个 dev server，已在跑时需先结束旧进程。

### 2.5 验证

1. 打开 `/login`，输入 `AUTH_PASSCODE`，登录后应默认落到 `/graph`。
2. 进 `/import` 上传一个 `.md` 文件，导入后 `/notes` 能看到文档与知识点数。
3. 打开 `/graph`，应看到力导向图；按 `Ctrl/Cmd+K` 能弹出搜索浮层。
4. 进 `/study/[segmentId]` 作答并揭晓参考答案，`/progress` 出现自测活跃度。

若任一步失败，先查 [常见问题排查.md](./常见问题排查.md)。

## 3. 脚本全表

| 命令 | 实际执行 | 用途 | 备注 |
|---|---|---|---|
| `npm run dev` | `next dev` | 开发服务器（Turbopack） | 建议加 `--hostname 127.0.0.1` |
| `npm run build` | `next build` | 生产构建 | **需要 `DATABASE_URL`**，缺变量会失败 |
| `npm run start` | `next start` | 启动生产构建 | 需先 `build` |
| `npm run lint` | `eslint` | 代码检查 | ESLint 9 + `eslint-config-next` |
| `npm run typecheck` | `tsc --noEmit` | 类型检查 | 不产出文件 |
| `npm run test` | `vitest run` | 单元/组件测试 | 43 个测试文件（`src/**/*.test.ts(x)`） |
| `npm run test:watch` | `vitest` | 监听模式 | — |
| `npm run test:e2e` | `node scripts/run-e2e.mjs` | Playwright 回归 | 首次先 `npx playwright install chromium` |
| `npm run perf:graph` | `node scripts/measure-graph.mjs` | 图谱性能测量 | 输出帧率数据 |
| `npm run db:generate` | `drizzle-kit generate` | 生成迁移 SQL | 改动 `src/db/schema.ts` 后执行 |
| `npm run db:migrate` | `node --env-file=.env.local scripts/apply-migrations.mjs` | 执行迁移 | 生产部署后需手工跑一次 |
| `npm run db:migrate:check` | 同上 + `--dry-run` | 只读检查 | 升级前建议先跑 |
| `npm run db:push` | `drizzle-kit push` | 直接推 schema | 仅开发期快速试验 |
| `npm run db:studio` | `drizzle-kit studio` | 数据浏览 | 需可连库 |

## 4. 质量门禁（提交前）

```bash
npm run typecheck
npm run lint
npm run test
npm run build      # 需要 DATABASE_URL
npm run test:e2e   # 需要可启动的 dev/build 环境
```

CI 已在 `.github/workflows/ci.yml` 中串起 test / lint / typecheck / build / E2E。

## 5. 压测图谱

```bash
# 生成三档 fixture（写入 public/fixtures/，该目录被 .gitignore 忽略）
node scripts/gen-graph-data.mjs                      # 默认档
node scripts/gen-graph-data.mjs -n 5000 -c 20 -d 6 --out public/fixtures/graph-mid.json --seed 7
```

| 档位 | 文件 | 规模 |
|---|---|---|
| small | `public/fixtures/graph-small.json` | 500 节点 |
| mid | `public/fixtures/graph-mid.json` | 5000 节点 |
| large | `public/fixtures/graph-large.json` | 8000 节点 |

访问 `/graph?fixture=graph-small` 即进入压测模式，顶部会显示「压测数据模式」徽标。fixture 不入库，与真实数据（`/api/graph`）完全隔离。

## 6. 部署到 Vercel（个人自用）

1. 推送到 GitHub，Vercel 导入仓库。
2. 配置环境变量：`DATABASE_URL`、`AUTH_PASSCODE`（可选 `SETTINGS_ENCRYPTION_KEY`、`R2_*`、LLM 回退变量）。
3. 首次部署后在本机指向生产库执行一次 `npm run db:migrate`。
4. 已知平台边界：请求体上限约 4.5MB（超大 md 分次粘贴）；可能多实例，进程内缓存为 best-effort。
