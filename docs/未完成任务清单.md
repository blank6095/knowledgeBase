## 0. 阅读说明

### 0.1 状态定义

| 状态 | 含义 |
|---|---|
| 未开始 | 代码库中无任何相关实现痕迹 |
| 部分完成 | 已有可复用的基础设施或部分实现，但主链路未接通 |
| 条件未触发 | 方案自带立项阈值，当前数据未达阈值，按设计暂不启动 |
| 待决策 | 需要产品或架构层面的确认才能动工 |
| 待验证 | 实现已存在，但缺少压测/浏览器验证数据 |

### 0.2 优先级定义

| 级别 | 判定标准 |
|---|---|
| P1 | 低改动、低风险、有明确收益；或为后续任务的前置证据 |
| P2 | 需要中等改造或产品确认，收益明确但非阻塞 |
| P3 | 依赖规模/数据条件触发，或属技术债与文档治理 |

### 0.3 信息可信度分级

本文档对三类信息做显式标注，避免与核实事实混排：

- **已核实**：来自本轮代码读取或 `git log`，可直接引用。
- **假设**：工作量与排期由任务粒度推算，未获负责人确认。
- **待确认**：仓库内无来源（对接人、目标设备矩阵、立项决策）。

> 对接人与预计完成时间的说明：仓库内**不存在** `CODEOWNERS`、团队成员清单或会议/IM 记录。因此本文所有「负责人」字段标注为**待指定**，排期标注为**假设**，不以推测填充。
