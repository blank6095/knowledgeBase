# 大模型调用优化方案（知识库使用效能）

> 基线基于 2026-10-25 的实现现状（v11–v14 已落地：设置页/RAG/拆解聚合/摘要/指纹缓存/学习者画像）。
> 诊断所引文件均已核实。目标：让每一次大模型调用**更省、更快、更准、更懂学习者**，服务
> 「检索 → 拆解/聚合 → 学习」的核心闭环。

## 1. 现状基线（已核实）

### 1.1 调用面清单（6 个调用点）

| 调用点 | 位置 | 频率 | 上下文 | 缓存 |
|---|---|---|---|---|
| 问知识库 | api/ai/ask | 高 | RAG 材料 top6 + 画像块 | 无 |
| 语义拆解 preview | api/ai/split-preview | 中 | RAG 邻居 + 画像 | 指纹缓存（256 LRU） |
| 语义聚合 preview | api/ai/aggregate-preview | 中 | RAG 邻居 + 画像 | 指纹缓存 |
| 导入语义拆分 | api/notes（aiSplit） | 低 | 按标题检索 + 画像 | 无（走 semanticSplit） |
| 摘要生成 | api/segments/[id]/summary | 低（懒生成） | 标题+内容 | 库缓存（segments.summary） |
| 测试连接 | api/ai/test | 极低 | 最小请求 | 无 |

### 1.2 已有优化

- 两步制铁律（preview→apply，LLM 输出永不直接写库）；失败降级不阻断。
- 双上下文注入：RAG 知识块 + 学习者画像块（learner-profile.ts，含 60s 缓存派生）。
- 建议类问题专用路由（ask 的 ADVICE_RE 正则 → 薄弱×中心性检索）。
- preview 指纹缓存（内容+模型；画像不参与 key——单用户可接受取舍，已在代码注释写明）。

### 1.3 已知缺口（本方案靶点）

| # | 缺口 | 位置 | 影响 |
|---|---|---|---|
| G1 | **零可观测**：不捕获 usage（token 数）、无调用日志 | llm.ts chatCompletion 只解析 choices | 成本是黑盒，一切优化无从量化 |
| G2 | 无 max_tokens：输出长度完全靠 prompt 约束 | llm.ts:57（body 仅 model/messages/temperature) | 极端输出失控（成本+时延） |
| G3 | 无重试：瞬时失败（限流/网络）直接报给用户 | llm.ts 无重试逻辑 | 一次抖动 = 一次功能失败 |
| G4 | 导入语义拆分逐段串行 await | api/notes/route.ts:95-103 | 5 段上限时导入耗时 = 5×单次时延 |
| G5 | ask 无流式：整段回答生成完才返回 | api/ai/ask | 长回答首字时延高 |
| G6 | DB 读失败误报"未配置大模型" | llm.ts getLlmConfig 静默回退 env | 网络闪断被当成配置问题 |
| G7 | 请求无并发护栏 | — | 并发 preview/导入可能触发限流 |

## 2. 目标与原则

**四轴目标**：成本（token/次与日用量可观测、有上限）· 时延（ask 首字、导入总时长）· 质量（拆解子段可用率、回答有据率）· 个性化（画像覆盖率）。

**三铁律（延续既有纪律）**：① preview→apply 两步制；② LLM 任何失败降级不阻断；③ 零新增依赖（流式用原生 SSE）。

**护栏（建议值，接近日志后校准）**：单次输入 ≤4k token；单次输出 ≤2k token（拆解 8 段上限天然受限）；单日调用 ≤200 次 / token ≤50 万。

## 3. 分层措施

### L1 调用层（省与快）

| 措施 | 做什么 | 成本 | 收益 | 验证指标 |
|---|---|---|---|---|
| L1-1 调用可观测（**先行**） | chatCompletion 返回 {text, usage}；新表 llm_calls（迁移 0006，注意重放陷阱需单独执行）：kind/model/inTok/outTok/ms/cached/error/createdAt；设置页加用量小节（近 7 天聚合） | 低 | 一切优化的前提；成本黑盒变透明 | 每次调用一行日志；设置页可见日 token |
| L1-2 输出预算 | chatCompletion 增 max_tokens 参数（默认 2048，拆解 4096）；超限错误可读化 | 低 | 防失控输出 | 构造超长回答场景被截断且有提示 |
| L1-3 失败重试 | 429/5xx/网络错误指数退避重试 1 次（间隔 1.5s）；4xx 不重试 | 低 | 瞬时抖动不再打到用户 | mock 429 场景第二次成功 |
| L1-4 导入并行 | aiSplit 逐段串行 → Promise.allSettled 并发（并发 ≤2）；成功数/失败数语义不变 | 低 | 导入总时长 ≈ ceil(5/2)×单次 | 5 段导入耗时对比 |
| L1-5 ask 流式 | ask 改 SSE 流式返回（前端逐字渲染，来源列表随末包返回）；降级：非流式客户端走现有整段 | 中 | 首字时延从"整段生成"降到"首 token" | 首字时间对比 |
| L1-6 模型分档 | llm.ts 增 MODEL_TIERS：{fast: 摘要/测试连接, default: 拆解/聚合/ask}；设置页可选 fast 档模型 | 低 | 低复杂任务用轻档省钱省时 | 各档 token 单价对比表（人工） |
| L1-7 并发护栏 | 进程内信号量（≤3 并发），超出排队 | 低 | 防限流雪崩 | 并发 10 次 preview 无 429 |
| L1-8 未配置文案修复 | getLlmConfig 区分「DB 读失败」（503 + 网络提示）与「确实未配置」（503 + 设置页指引） | 低 | 消除误导（G6，上轮已记录） | 断网场景错误文案正确 |

### L2 检索与上下文层（更准）

| 措施 | 做什么 | 成本 | 收益 | 适用条件 |
|---|---|---|---|---|
| L2-1 上下文预算 | RAG 块（top6×120 字）+ 画像块（400 字）+ 材料的总预算 ≤3k token，超限优先保材料、裁 RAG 摘要 | 低 | 防 prompt 膨胀（尤其导入长段时） | 立即 |
| L2-2 ask 缓存 | 同 query+材料指纹+声明层文本 的 ask 结果缓存（TTL 24h，复用 llm_cache 加 kind='ask' 与 expiresAt 列） | 低 | 重复提问零成本 | 立即 |
| L2-3 嵌入检索（pgvector） | 关键词 → 混合（现）→ 嵌入召回补足同义不同词 | 高 | 召回率提升 | **触发条件：ask"答非所问"率 >30%（两周抽样）才立项** |

### L3 学习闭环层（更帮你学，按 v14 延伸）

| 措施 | 做什么 | 依赖 | 优先级 |
|---|---|---|---|
| L3-1 「解释这段」 | 阅读态选区 popover 增"AI 解释"：选中文本 + 所在段 + 画像 → 按掌握深度解释（薄弱多铺垫） | 画像（已具备） | P1 |
| L3-2 「联系两概念」 | 图谱选两节点 → 对比/关联解释（材料=两段内容+共同邻居） | RAG（已具备） | P2 |
| L3-3 自测三问 | 薄弱段生成 3 道自查问题（非选择题，Roadmap"测验模式"的轻量版） | 画像 | P2 |
| L3-4 薄弱推送 | 概览顶部一条"今天建议先看《X》"（薄弱×中心性 top1，纯规则不调 LLM） | — | P1（零成本） |
| L3-5 学习周报 | 画像快照按周落库 + LLM 生成一页周报（新亮起的灯/变暗的灯/下周建议） | L1-1 观测 | P2 |

## 4. 最小可行路径（只做 3 件，先看见再优化）

1. **L1-1 可观测**（llm_calls 表 + usage 捕获 + 设置页用量）——没有它，其余优化都是感觉；
2. **L1-2 + L1-3 预算与重试**——一次改动锁死失控与抖动两类事故；
3. **L1-4 导入并行**——最可感知的时延改善，改动最小。

其余按 L1-8 → L2-2 → L1-5 → L1-6/L1-7 → L3-1/L3-4 顺序推进；L2-3 与 L3-2/L3-3/L3-5 按触发条件立项。

## 5. 度量与通过标准

| 指标 | 现状 | 目标 |
|---|---|---|
| 调用可观测率 | 0% | 100%（每调用一行 llm_calls） |
| ask 首字时延 | = 整段生成（约 5–20s） | 流式后 ≤2s |
| 导入 5 段语义拆分耗时 | ≈5×单次 | ≤3×单次（并发 2） |
| preview 缓存命中率 | 未度量 | 可在设置页读出；调参场景 ≥60% |
| 瞬时失败用户可见率 | 100%（无重试） | ≤50%（重试 1 次后） |
| 日 token 用量 | 黑盒 | 设置页可见 + 超护栏（50 万/日）提醒 |

## 6. 迭代变量（可测试）

| 变量 | 取值 | 观测方式 |
|---|---|---|
| V1 模型分档映射 | fast 档用哪个 id | 摘要质量抽检 vs token 成本对比 |
| V2 ask 缓存 TTL | 6h / 24h / 72h | 命中率 vs 画像漂移感知 |
| V3 嵌入检索立项线 | 答非所问率 20% / 30% | 两周 ask 抽样 20 问人工判定 |

## 附：执行注意事项

- 迁移 0006（llm_calls）生成后**单独执行**（db:migrate 全量重放会卡死在 0000，已知陷阱）。
- llm_calls 含 error 字段但**不得记录 prompt 内容与画像文本**（隐私），只记维度与用量。
- L1-5 流式改造涉及 api client 与 /ask 页两处，遵守既有 reduced-motion 与骨架屏约定。
- 本方案与 v14 画像层正交：画像已注入三个消费方，任何 L1/L2 措施不得破坏 profileSummary 响应字段。
