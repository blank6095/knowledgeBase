## 2. 修复方案（可直接执行）

> 约定：每个任务完成后必须跑 `npm run typecheck && npm run lint && npm run test && npm run build`，涉及页面跳转/流程的再跑 `npm run test:e2e`。移动端验收用 Playwright 量取实际像素，不接受「类名看起来对」。

### T1（P0）修复移动端段编辑工具行 —— 对应 UX-03

- **目标**：320–414px 下标题可编辑、工具可用、无横向溢出。
- **涉及**：`src/components/SectionEditor.tsx`（必要时同步 `SegmentEditCard.tsx`）。
- **改动要求**：工具行改为可折行布局（标题独占一行）或将「上移/下移/插入/拆解/删除」在 `<sm` 收进一个「更多」菜单；保留桌面现有单行布局；按钮触控高度 ≥40px；首段禁用上移、末段禁用下移（并入 UX-18）。
- **依赖**：无。
- **验收**：390px 与 320px 实测标题输入框宽 ≥120px 或标题独占整行；`document.documentElement.scrollWidth - innerWidth === 0`；桌面 1440px 布局与改前一致；`move` 边界按钮 `disabled`。

### T2（P0）助手对话化与异常收尾 —— 对应 UX-06 / UX-07 / UX-08 / UX-09

- **目标**：提问与历史可见、流异常有明确收尾、上下文失败可感知、失败改动可重试。
- **涉及**：`src/app/ask/page.tsx`（渲染结构改为消息列表）。
- **改动要求**：① 以 `history` 渲染用户/助手消息列表，当前流式回答作为最后一条追加，不再用单 `result` 覆盖；② 流结束既无 `done` 又无内容时进入错误态并保留输入内容；③ chips 全部/部分拉取失败时显示「N 个知识点未能带入」提示，不静默；④ `error` 状态的改动项提供「重试」，可单独重新应用。
- **依赖**：建议先做 T3 的 401 处理，避免重复改错误分支。
- **验收**：连续 3 轮提问后 3 个用户问题与 3 条回答均在屏；mock 一个空 SSE 流出现错误提示且输入框内容保留； mock chips 接口 500 出现提示；新增 Vitest 覆盖消息列表渲染与重试逻辑（可抽纯函数）。
