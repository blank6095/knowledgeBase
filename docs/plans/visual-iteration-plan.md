## 0. 结论摘要

| 判断 | 依据 |
|---|---|
| 主题与配色**不是**当前不满意的主因 | 实景中暖墨黑 + 琥珀灯光的隐喻一致、层级色（`surface/elevated/line`）干净，换色只会重建返工 |
| 真正的问题是**信息架构与视觉层级** | 首页 5 个同权重区块 + 两个实心琥珀按钮竞争；助手页整页只显示最新一条回答，不显示用户问题 |
| 真正的问题之二是**小字对比度与窄屏版式** | `text-faint` 在卡片上仅 3.16:1、在浮层上 2.72:1，却承担 12px 说明文字；375px 下热力图日期折行、优先项标题被截断 |
| 之前 3 份方案（ux / systematic / GPT 建议）**状态已漂移** | systematic §5.4 仍把已完成的 CSP、Key 加密、静默超时列为待办；project-context 仍写"无 CSP""图谱未做视口裁剪" |
| 剩余 8 项开放任务**多数不是当前瓶颈** | 全部依赖产品决策、依赖引入授权或真实数据阈值；与"界面不满意"没有因果关系 |

**因此本轮建议：不新增功能，先做 8 项体验缺陷修复 + 6 项体验提升 + 6 项组件统一 + 4 项可选优化，同时把 8 项开放任务收敛为 4 个决策项。**

## 3. 优化项（问题与影响 — 优化目标 — 具体改动 — 预期效果）

### 阶段 0：必须完成（缺陷修复，不改业务逻辑）

#### G1 助手丢失对话上下文
- **问题与影响**：用户提问后输入框清空、问题消失，回答只剩最新一条；多轮对话在界面上表现得像单次问答，无法核对回答对应的问题。这是助手页最大的结构缺陷。
- **优化目标**：让助手呈现为可回看的对话，而不是"结果文本框"。
- **具体改动**：`src/app/ask/page.tsx` 保留并渲染 `history`（用户问题 + 助手回答 + 来源 + 确认卡）；当前轮次在流式时以独立状态行展示；发送按钮固定文案"发送中…"，`status` 移到输入框上方状态行。
- **预期效果**：任一轮回答都能对应到原问题；按钮宽度稳定；不改动 SSE 协议与 Agent 逻辑。

#### G2 首页双主按钮与主行动稀释
- **问题与影响**：页头"导入知识"与卡片内"开始回忆"同为实心琥珀；四个同权重卡片让首屏没有明确主线，用户仍需判断"先做哪个"。
- **优化目标**：首屏只有一个主动作，其余降级为次级信息。
- **具体改动**：页头"导入知识"改为次级按钮（描边）；今日学习卡片保留唯一实心主按钮"开始回忆 →"；薄弱/未读合并为次级列表（见 G9）；统计带改为一行文字。
- **预期效果**：打开首页 3 秒内知道下一步；主按钮唯一。

#### G3 辅助文字对比度不足
- **问题与影响**：`text-faint`(#6e675c) 在卡片上 3.16:1、浮层上 2.72:1，却用于图谱说明、导入说明、复习间隔、日期等**功能性**文字；热力图日期在其自身亮底上仅约 1.66:1，几乎不可读。
- **优化目标**：功能性文字达到 WCAG AA 4.5:1；装饰性文字保留弱层级。
- **具体改动**：`globals.css` 将 `--color-faint` 提亮到满足 4.5:1（对 `surface`）的色值；建立使用边界——说明/帮助/日期/元数据改用 `text-muted`，`faint` 只留给序号、分隔符等装饰；热力图亮格前景改 `accent-ink`。
- **预期效果**：小字可读；暗色层级仍在但不再"看不清"。

#### G4 热力图在桌面与移动端均不可用
- **问题与影响**：桌面每格约 80px 高、占比过大；375px 下日期折行、数字挤到第三行；亮格数字对比不足。
- **优化目标**：桌面紧凑、移动端不破版、数字始终可读。
- **具体改动**：改为固定格宽（桌面约 56px）+ `grid-flow-col` 自适应；移动端日期仅显示日（`dd`）或整块横向滚动；亮格前景用 `accent-ink`，最高底色不透明度降到 0.6；补键盘可达的每日明细（替代 hover-only `title`）。
- **预期效果**：热力图从"占半屏的大格子"变为"一眼扫完的一行/两行"；375px 无折行。

#### G5 知识库列表 hover 失效与移动端信息缺失
- **问题与影响**：`group-hover` 无对应 `group` 类，标题 hover 高亮永不触发；移动端隐藏日期，仅剩"N 点"。
- **优化目标**：交互反馈真实生效，移动端信息不缺失。
- **具体改动**：`notes/page.tsx` 链接补 `group`；移动端元数据改为两行（点数 + 日期）或保留日期；补空结果与搜索态的统一反馈。
- **预期效果**：hover 有响应；移动端可判断文档新鲜度与体量。

#### G6 窄屏弹层越界与错误静默
- **问题与影响**：批注弹层固定 288px 宽而横向仅保留 120px 边距，320/375px 下会被裁切；节级笔记保存失败、删除标注失败、用量加载失败均无提示，用户以为成功。
- **优化目标**：弹层不越界；失败必须可见。
- **具体改动**：弹层按实际宽度做碰撞检测（含 `max-w-[calc(100vw-2rem)]`），移动端改为底部 Drawer；失败路径补 `InlineFeedback`（`role="alert"`）；目录摘要浮层改为向左展开或统一 Popover。
- **预期效果**：窄屏不出现被裁切浮层；写操作失败有明确反馈。

#### G7 导入成功态主次倒置
- **问题与影响**：导入成功后内容已清空，但主按钮仍是"导入"，点击只会得到"请粘贴内容"的错误；真正的下一步"查看文档"只是文字链接。
- **优化目标**：成功态直接引导到下一步。
- **具体改动**：`import/page.tsx` 成功态把"查看文档"设为主按钮，"继续导入"降为次级；错误提示区分"未填写内容"与"服务失败"。
- **预期效果**：导入后一步到位，不产生无效点击。

#### G8 文档状态漂移（本轮新发现）
- **问题与影响**：`systematic-iteration-plan.md` §5.4 把已完成的 CSP/Key 加密/静默超时列为待办；`project-context.md` §5.3 仍写图谱"未做视口裁剪/quadtree/坐标持久化"，§10/§13 仍写"无 CSP"；`未完成任务清单.md` §6.2 仍写 A2"无缓存读写调用"、D1"无 CSP"。文档互相矛盾会持续误导后续迭代。
- **优化目标**：四处文档与代码一致。
- **具体改动**：统一改为"已完成 + 落地位置"表述；`systematic-iteration-plan.md` §5.4 表按当前实际重写；`project-context.md` §5.3/§10/§13 修正；清单 §6.2 关键代码位置刷新。
- **预期效果**：不再出现"已完成却标待办"的二次返工。

### 阶段 1：体验提升（信息架构与版式）

#### G9 首页信息架构收敛
- **问题与影响**：首页同时存在两套学习入口（今日学习 vs 薄弱/未读）与两套指标（首页指标条 vs 复盘页指标卡），推荐语义重叠、同一知识点可能重复出现。
- **优化目标**：首页回答"现在做什么"，其余交给复盘页与图谱。
- **具体改动**：首页保留今日学习为主卡；薄弱 + 未读合并为「继续探索」次级列表（可折叠）；四项指标压成一行；统计带降为页脚级文字；标题由"概览"改为"今日学习"，与复盘页的"返回今日学习"一致；页脚移除技术栈文案。
- **预期效果**：首页模块从 5 块降到 3 块，首屏只保留"今天要做的 3 件事"。

#### G10 容器与栅格统一
- **问题与影响**：同一站内并存 `max-w-2xl`、`max-w-[42rem]`、`max-w-4xl` 三种宽度，1440px 下首页内容偏窄、两侧空白大；助手 42rem 栏与列表 4xl 宽列表节奏不一致。
- **优化目标**：全站形成 4 档固定容器，页面节奏统一。
- **具体改动**：定义容器 token（reading 42rem / form 48rem / wide 64rem / full 图谱），首页/复盘/列表用 wide，助手/学习/设置/文档详情用 reading，导入用 form；AppShell 侧栏宽度作为布局变量统一引用。
- **预期效果**：不同页面的左右留白节奏一致，不再有"某页很挤某页很空"。

#### G11 指标呈现统一
- **问题与影响**：同一组 7 天指标在首页是 12px 文字条、在复盘页是 4 张大卡，两套视觉语言。
- **优化目标**：同一指标全站一种呈现（数值样式 + 标签 + 环比）。
- **具体改动**：抽 `Metric` / `MetricCard` 组件，首页用紧凑版、复盘用卡片版，复用同一色与排版规则。
- **预期效果**：指标不再需要两套心智模型。

#### G12 复盘页零值态
- **问题与影响**：无自测记录时，4 张 0 值大卡仍占满一屏，把"本周结论"挤到最上方之外。
- **优化目标**：空数据时页面重心回到结论。
- **具体改动**：四项指标在全部为 0 时压缩为一行摘要（"本周尚未自测"），有数据时才展开为卡片；热力图保留但压缩高度。
- **预期效果**：空态页面从"4 张 0"变成"一句结论 + 去开始"。

#### G13 知识库列表信息密度
- **问题与影响**：每行信息稀疏（标题 + 灯点 + 点数 + 日期），标签仅在宽屏出现，移动端更少。
- **优化目标**：列表在一次扫视中提供"是什么 / 多大 / 新不新 / 亮了几盏灯"。
- **具体改动**：行内补文档级记忆概览（复用 `MEMORY_TIER_META` 四档点色的小色条或平均记忆度文字）；标签在 `sm` 起显示；hover 显示次级信息（创建时间、标签数），移动端不依赖 hover。
- **预期效果**：文档列表可作为"知识地图"使用，而不仅是入口列表。

#### G14 助手空态与能力边界
- **问题与影响**：助手页空态仅 3 个预设胶囊 + 一行提示，用户不知道"它能做什么、不能做什么"，也不知道"每一步都会确认"意味着什么。
- **优化目标**：首屏即建立能力预期，降低第一次使用的试错。
- **具体改动**：空态改为 3 张能力卡（问答检索 / 读取原文 / 提议改动）+ 2 个示例问题入口；预设按钮明确语义（点击即发送还是填充，标注清楚）；保留"改动需确认"的说明。
- **预期效果**：新用户无需试错即可发起第一问。

#### G15 图谱设置面板的移动端形态
- **问题与影响**：设置面板固定 300px 宽、绝对定位、无 `max-height` 与内部滚动；「力」标签下 4 个滑杆在横屏或小高度设备上会超出视口。
- **优化目标**：移动端设置可用且不遮挡画布核心区。
- **具体改动**：移动端改为底部 Drawer（限高 70vh、内部滚动），桌面保持当前下拉面板；筛选全部关闭时给出明确空态与"重置筛选"入口。
- **预期效果**：移动端图谱不再出现"面板超出屏幕"。

#### G16 段编辑工具栏窄屏拥挤
- **问题与影响**：标题输入与 8 个操作（上移/下移/插入/预览/AI 拆解/删除）同处一行不换行 flex，窄屏下标题被压到几乎不可用。
- **优化目标**：小屏可完成"改标题 + 保存"。
- **具体改动**：标题独占一行；结构类操作收进「更多」菜单（保留键盘可达与 aria 标注）；删除保持独立危险按钮。
- **预期效果**：375px 下编辑卡不再横向溢出。

#### G17 触控目标统一
- **问题与影响**：移动导航按钮约 32px、图谱按钮 32–36px、批注色点 16–20px，低于移动端可点击建议值。
- **优化目标**：主要触控目标 ≥44px。
- **具体改动**：定义 32 / 40 / 44 三档控件高度；移动端主操作与导航按钮使用 44px；批注色点保持视觉尺寸但扩大到 44px 透明点击区。
- **预期效果**：移动端误触率下降，视觉密度不变。

### 阶段 2：组件统一（消除重复实现，零新增依赖）

#### G18 基础控件抽取
- **问题与影响**：主按钮、输入框、图标按钮在设置/导入/编辑卡/编辑器中机械重复约 20 处，改一处样式要改多处，长期漂移。
- **优化目标**：控件外观与可访问性单点定义。
- **具体改动**：新增 `Button`（primary/secondary/ghost/danger × sm/md/touch × loading）、`IconButton`（统一点击区 + `aria-label`）、`Input`/`Textarea`、`Field`（label/hint/error/required）；按页面替换，保留现有 handler 与状态结构。
- **预期效果**：视觉一致性由代码结构保证，而非人工同步。

#### G19 页面结构件抽取
- **问题与影响**：页头、容器、区块标题各页手写；设置页用 `<p class="text-tag uppercase">` 冒充标题，无 `h2`/`label`，语义与层级都弱。
- **优化目标**：页面结构语义化、可复用。
- **具体改动**：新增 `PageContainer`（四档宽度）、`PageHeader`（标题/描述/返回/actions）、`SectionHeader`（`h2` + 说明 + 右侧行动）；设置页改真实 `h2` 与 `<label htmlFor>`。
- **预期效果**：标题层级可被辅助技术正确识别，页面节奏统一。

#### G20 反馈与空态组件抽取
- **问题与影响**：错误一律是裸红字，无重试与去向；设置页把"加载中/失败/无数据"合并成同一空态（误导）；动态反馈无 `aria-live`；`PageSkeleton` 已定义却未使用。
- **优化目标**：状态表达统一且诚实。
- **具体改动**：新增 `EmptyState`/`ErrorState`（含重试与安全去向）、`InlineFeedback`（success/warn/danger/info + `aria-live`）；启用并扩展 `PageSkeleton`；设置页拆成 loading/error/empty 三态。
- **预期效果**：任何"没数据"都不再被误显示为"没有记录"。

#### G21 图标语言统一
- **问题与影响**：`⚙✎✕✨✦▶⏸` 与 AppShell 的线性 SVG 图标并存，同类控件外观不一。
- **优化目标**：一套图标语言（零新增依赖）。
- **具体改动**：把 AppShell 的 SVG 图标抽为共享 `icons.tsx`，逐步替换页面内的字符图标；替换时同步补 `aria-hidden` / `aria-label`。
- **预期效果**：按钮与入口视觉一致，字符符号不再与线性图标混排。

#### G22 弹层体系统一
- **问题与影响**：`AiOverlay` 已有 dialog/Esc/遮罩但缺焦点陷阱、滚动锁与焦点恢复；批注、目录摘要、图谱设置各写各的定位逻辑。
- **优化目标**：一套弹层原语，覆盖浮层/抽屉/气泡。
- **具体改动**：以 `AiOverlay` 为基础补焦点管理，抽出 `Dialog` / `Drawer` / `Popover`（含碰撞检测）；批注、目录摘要、图谱设置迁移到同一套。
- **预期效果**：弹层行为一致，窄屏不再需要每处单独打补丁。

#### G23 状态色单一出口
- **问题与影响**：热力图底色、标注默认色、图谱新分组色在页面内硬编码，Canvas 处还靠注释与 CSS 手工同步，漂移风险高。
- **优化目标**：色值单一来源。
- **具体改动**：把可共享的色值收敛到 `lib/theme.ts`（与 `MEMORY_TIER_META` 同层），Canvas 需要的部分显式说明；热力图透明度改为由同一常量派生。
- **预期效果**：改一次主题即全站生效，不会出现"某页还是旧色"。

### 10.2 组件用法

```tsx
import InlineFeedback from '@/components/InlineFeedback';
import ErrorState from '@/components/ErrorState';

// 1) 行内反馈：错误会被立即播报，其余为礼貌播报
<InlineFeedback tone="success">已保存</InlineFeedback>
<InlineFeedback tone="danger">保存失败，请重试</InlineFeedback>

// 2) 页面级错误：必须给重试与安全去向
<ErrorState message="数据库连接失败" onRetry={() => refetch()} />
<ErrorState message="读取失败" action={{ href: '/graph', label: '去看图谱' }} />
```

### 10.3 纯函数用法

```ts
import { bestContrastForeground, compositeOver, contrastRatio } from '@/lib/ui/contrast';
import { clampPopover, POPOVER_WIDTH } from '@/lib/ui/geometry';
import { PALETTE } from '@/lib/ui/theme';

// 亮底自动选字色（热力图高亮格）
const bg = compositeOver(PALETTE.surface, PALETTE.accent, 0.48);
const fg = bestContrastForeground(bg, [PALETTE.accentInk, PALETTE.primary]);

// 浮层不越界：返回可直接写进 style 的坐标
const pos = clampPopover({
  anchorX: rect.left + rect.width / 2,
  anchorY: rect.top - 10,
  width: POPOVER_WIDTH,
  height: 220,
  viewportWidth: window.innerWidth,
  viewportHeight: window.innerHeight,
});
<div style={{ left: pos.left, top: pos.top }} />
```

### 10.4 扩展指引

- **新增颜色**：先改 `src/app/globals.css` 的 `@theme`，再同步 `src/lib/ui/theme.ts`；`ui-theme.test.ts` 会校验对比度，低于 4.5:1 直接失败。
- **新增浮层**：一律用 `clampPopover` 计算位置，不要再写固定边距（如历史上的 `clampX`）；窄屏一律加 `max-w-[calc(100vw-1.5rem)]`。
- **新增反馈**：用 `InlineFeedback`（局部）与 `ErrorState`（整块），不要再写裸红字；错误一律 `role="alert"`。
- **给暗色底加文字**：先用 `contrastRatio` 自检，再决定用 `primary/muted/faint`；纯装饰才用 `faint-decor`。
