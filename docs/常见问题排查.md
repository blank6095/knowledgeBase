## 1. 启动与开发服务器

### 1.1 页面不水合（骨架屏常驻）

**现象**：`/graph`、`/`、`/notes` 等页面一直显示骨架，`canvas` 不存在，`Ctrl/Cmd+K` 无反应；浏览器控制台出现 HMR WebSocket 握手错误（如 `ERR_INVALID_HTTP_RESPONSE`）；直接 fetch `/api/graph` 返回 200，但页面不更新。

**原因**：`next dev` 默认绑定 `localhost`，在部分 Windows 环境下 HMR WebSocket 握手失败，客户端代码不执行，React 不水合。

**处理**：

```bash
npm run dev -- --hostname 127.0.0.1 --port 3300
```

确认浏览器控制台出现 `[HMR] connected`，且页面骨架消失。后续截图、E2E、手工验证都建议固定这个启动方式。

### 1.2 单项目只允许一个 dev server

**现象**：启动时输出 `⨯ Another next dev server is already running`，或新端口能起但行为异常。

**原因**：Next 16 对同一项目加了单实例锁；上一个 dev 进程（可能不是当前终端起的）仍存活。

**处理**（Windows PowerShell）：

```powershell
# 找出所有 next dev 进程
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'next dev' } |
  Select-Object ProcessId, CommandLine

# 结束指定进程（含子进程）
taskkill /PID <PID> /T /F
```

确认无残留后再启动；不要同时开两个 `npm run dev`。

### 1.3 端口被占用

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen | Select-Object OwningProcess
```

改用其他端口：`npm run dev -- --port 3300`（同时保留 `--hostname 127.0.0.1`）。

## 2. 构建与类型检查

### 2.1 `npm run build` 失败：缺少 DATABASE_URL

**原因**：`next build` 会导入所有 Route Handler 模块，`src/db/index.ts` 在模块加载时校验 `DATABASE_URL`；惰性 Proxy 只保证「无查询不连接」，不保证「无变量不报错」。

**处理**：构建环境注入真实的 `DATABASE_URL`（CI 中同样需要）。

### 2.2 类型检查报错但代码看起来没问题

- 先确认 `npm run typecheck`（`tsc --noEmit`）而不是 IDE 缓存。
- Next 16 的类型约定与旧版本不同（如 `LayoutProps`、`PageProps`）；改代码前先读 `node_modules/next/dist/docs/` 对应指南，不要按训练数据里的旧写法改。

### 2.3 Lint 与格式化冲突

`npm run lint` 使用 ESLint 9 + `eslint-config-next`；若新增文件被规则拦下，优先改代码而不是关规则。

## 3. 认证与数据库

### 3.1 登录失败

| 检查项 | 说明 |
|---|---|
| `.env.local` 是否有 `AUTH_PASSCODE` | 缺失时认证 fail-closed，任何口令都无法登录 |
| 是否改过口令 | 会话令牌是口令的哈希，改口令后旧 Cookie 立即失效，需重新登录 |
| 是否触发限流 | 10 分钟内失败 5 次会被拒绝；等待窗口结束或重启进程（限流为进程内） |
| 是否访问了错误的域名/端口 | Cookie 按域隔离，换端口等于换来源，需重新登录 |

### 3.2 数据库瞬时故障

系统对只读路径做了两层保护：

1. `src/lib/db-retry.ts` 识别瞬时连接错误并指数退避重试；
2. 仍失败则 `src/lib/db-read.ts` 回退最近一次成功快照，响应头 `X-Cache: STALE`（数据可能略旧）；
3. 完全不可用时返回 503，页面显示「重试」按钮（`ErrorState`）。

排查顺序：Neon 控制台看项目是否休眠/超配额 → 检查 `DATABASE_URL` 是否 Pooled → 本地 `npm run db:migrate:check` 是否可连。

### 3.3 写操作失败

导入、段编辑/移动/删除、AI 拆解/聚合都在 Neon HTTP batch 事务中提交，失败会整体回滚，不会留下半成品。若持续失败，检查是否超出 Neon 免费层写入限制或请求体过大。

## 4. 图谱

### 4.1 图谱空白或节点很少

| 检查 | 处理 |
|---|---|
| 是否刚部署、库里无数据 | 先 `/import` 导入至少一篇 md |
| `/api/graph` 返回是否为空 | 直接访问接口确认 `nodes` 长度 |
| 是否在 fixture 模式但文件缺失 | 见 §4.2 |
| 是否被筛选条件过滤 | 打开设置面板「筛选」，重置记忆档位与关联类型 |

### 4.2 fixture 404

`public/fixtures/*.json` 被 `.gitignore` 忽略，新克隆的仓库没有这些文件。生成：

```bash
node scripts/gen-graph-data.mjs
# 或指定档位
node scripts/gen-graph-data.mjs -n 5000 -c 20 -d 6 --out public/fixtures/graph-mid.json --seed 7
```

### 4.3 图谱卡顿

- 8k 节点是当前生成器最大档；更大规模需要社区聚合或 WebGL（未实现，见 [未完成任务清单.md](./未完成任务清单.md) D2）。
- 关闭小地图、减少标签显示、折叠筛选范围可降低绘制成本。
- 用 `npm run perf:graph` 获取帧率数据，不要凭感觉判断回归。
- 注意：性能数字跨会话不可复现，比较必须在同一环境做 A/B。

### 4.4 图谱搜索没结果

- 搜索匹配标题、标签、摘要等字段；先用短关键词（如「TCP」）验证，再逐步加长。
- 搜索浮层需要页面已完成水合；若浮层打不开，先排查 §1.1。

## 5. 大模型与存储

### 5.1 「未配置大模型」

说明 DB 设置无 Key 且无环境变量回退。二选一：

1. 打开 `/settings` 填 API Key 与模型，保存即生效（无需重启）；
2. 配置 `DEEPSEEK_API_KEY`（模型缺省 `deepseek-v4-flash`）或 `LLM_API_KEY` + `LLM_MODEL`，然后重启。

提示文案若为「数据库暂时不可达」，则是读取设置失败（`db-down`），不是真的没配置；稍后重试或加环境变量回退。

### 5.2 测试连接失败

| 可能原因 | 处理 |
|---|---|
| 改过 `AUTH_PASSCODE` 且未设 `SETTINGS_ENCRYPTION_KEY` | 旧密文无法解密，重新填一次 Key |
| Key 错误 / 额度不足 / 地区限制 | 用 DeepSeek 官方接口先独立验证 |
| 网络超时 | 单次超时 60s；检查代理与出网策略 |
| 模型 id 不存在 | 用官方稳定别名或文档中存在的 id |

### 5.3 没有 R2 备份

`R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET` 任一缺失即跳过备份，导入本身不受影响。这不是故障，除非你明确需要原文备份。

### 5.4 AI 回答被截断

- 单次输出默认 `max_tokens=2048`（拆解类 4096）；长回答可能触顶。
- 流式有整流 60s 超时与 chunk 静默 30s 限制；超长回答可能在中途被断开。
- 同进程并发上限 3，排队过久也会表现为「卡住」。

## 6. 数据库迁移

### 6.1 「表已存在」

旧库有完整表结构但没有 `_kb_migrations` 版本表。迁移执行器会自动建立基线，不重放历史迁移；若仍报错，用 `npm run db:migrate:check` 查看待执行列表，确认没有手工改过 schema。

### 6.2 迁移中途失败

- 迁移按文件顺序执行，失败即停；修复后重跑会从失败文件继续。
- 不要手工改 `_kb_migrations` 记录，除非确认对应 SQL 已完整执行。
- 生产库执行前先在 Neon 控制台创建分支/备份。

### 6.3 `db:push` 与 `db:migrate` 混用

`db:push` 直接推 schema，不写迁移记录。开发期可用，但不要在生产使用，否则会与迁移历史分叉。

## 7. 测试与 E2E

### 7.1 E2E 跑不起来

```bash
npx playwright install chromium   # 首次
npm run test:e2e                  # 启动器会处理端口与环境
```

若提示端口占用，先按 §1.2 清理残留 dev server；若浏览器启动失败，确认本机 Chrome 可用（本仓库截图脚本使用 `channel: 'chrome'`）。

### 7.2 单测在 Windows 上偶发失败

`vitest.config.mts` 已限制 `maxWorkers: 2` 以规避 Windows 并发导致的假失败；不要随意调高并发。

### 7.3 E2E 断言与页面文案不一致

页面文案属于产品变更时，更新测试而不是放宽断言；不确定时先看 [功能说明.md](./功能说明.md) 的对应章节确认预期行为。

## 8. 安全与样式

### 8.1 CSP 拦截外链

`next.config.ts` 强制 CSP。新增图片域名、字体源或第三方脚本时必须同步更新 CSP，否则浏览器会拦截并报 `Refused to load ...`。

### 8.2 页面被 iframe 嵌入失败

`X-Frame-Options: DENY` 是刻意配置，禁止被嵌入；不要为了临时演示移除。

### 8.3 样式与设计令牌不一致

- 颜色/间距应使用 `src/lib/ui/theme.ts` 与 Tailwind 令牌，不写裸色值。
- 记忆档位颜色必须来自 `MEMORY_TIER_META`，不要另造一套语义。

## 9. 部署相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 部署后接口全 401 | 环境变量未配置或大小写错误 | 在 Vercel 项目设置中补齐并重新部署 |
| 导入大文件失败 | Vercel 请求体上限约 4.5MB | 分次粘贴导入 |
| 多实例下数据短暂不一致 | 进程内缓存只失效当前实例 | 个人自用可接受；必要时刷新页面 |
| 部署后表不存在 | 未执行迁移 | 在本机指向生产库执行 `npm run db:migrate` |

## 10. 求助前的最小信息包

提交问题前请附上：

1. 复现步骤与页面 URL（含 `?fixture=` 等参数）；
2. 浏览器控制台报错与网络请求状态码（是否 `X-Cache: STALE`）；
3. `npm run typecheck` / `npm run lint` / `npm run test` 的结果；
4. 启动命令（是否带 `--hostname 127.0.0.1`）与 Node 版本；
5. 是否配置了 R2 与 LLM（不需要贴出 Key）。
