## 3. 全局约束（源方向文档原文不变，适用于全部任务）

1. **不推翻业务底座**：不改 API、数据库、迁移；不改现有搜索、复习提交、幂等、记忆计算行为。
2. **§9 暂缓**：PDF/DOCX/网页/图片导入、大规模更换渲染引擎、节点皮肤商城、复杂粒子与持续动画、向量数据库迁移、大量新增 AI Agent 工具、一次性改造所有页面、数据库结构大改。
3. **§7 闸门**：第一轮不进入全站编码；T07 评审通过后才启动阶段 3–6。
4. **§5 代码组织**：`src/components/graph/universe/` 目录树为目标组织，不要求一次性创建全部文件；能复用现有组件就复用。
5. **§8 分配原则**：高能力模型承担设计决策 / 架构 / 视觉评审；Metis 承担有明确范围的组件实现；Trae 辅助局部修改与检查；豆包独立检查与文档对照；任何 Agent 不独立决定产品方向。
6. **§6 节奏**：每周 2h 设计评审 / 5h 实现 / 2h 浏览器验收 / 1h 文档与 Git 整理（**假设**，非工期承诺）。
7. **可分配性**：每任务仅改本任务允许范围，结果可独立检查；Q1–Q3 默认暂缓。
8. **保护既有工作区改动**（v1.2 新增，最高优先级）：基线 `c4c9591` 之外存在 2026-11-02 ~ 11-04 的**未提交改动**，它们不是本轮任务的产物。每项任务开始前必须执行 `git status --short` 并记录任务开始时的工作区状态；**不得覆盖、丢弃、重置、暂存或提交任务开始前已存在的未提交改动**；禁止擅自执行 `git reset --hard`、`git clean -fd`、`git checkout --`、`git stash` 等可能影响既有工作区内容的命令。任务完成时必须提供本任务新增/修改文件的 diff 清单，并**区分任务前已有改动与本任务产生的改动**。需要扩大修改范围时先停止并报告，不得自行扩权。多 Agent 协同时，文件边界与 Git 边界同等重要。

**表 4 · 页面展示内容 → 数据来源映射表**（v1.2 新增；T01 交付，**已核实**接口与字段，覆盖首页 / 图谱 / 知识详情 / 学习舱 / AI 浮层）

| 图谱记忆新鲜度 | `GET /api/graph` | `nodes[].memory`（读取时现算） | 支持 | 按既有记忆档位规则处理 |

| 图谱掌握证据 | 现有接口**无对应字段** | `recall_reviews.result` 为真实学习行为证据，仅经 `/api/learning/today` 的 `latestResult` 间接暴露 | **不支持全图谱** | **不显示掌握结论**；不得用 `viewCount` / `readingMs` / `memory` 推断掌握 |

> **掌握证据与待复习的数据依据（v1.2 结论）**：`GET /api/graph` 的节点只有 `id / title / memory / viewCount / readingMs / documentTitle / tags / summary / headingPath`，**没有掌握证据与待复习标记**；段详情接口也不含复习结果。因此本轮**不实现全局「掌握结论」外环**；T09 若保留青色外环，只能表达「该节点在 `/api/learning/today` 中存在真实复习记录（`latestResult`）」这一可核实事实，并标注为「有学习记录」，**不得把「读过」等同于「掌握」**。待复习标记只取 `reasonCode` / `nextReviewAt`，不根据记忆亮度猜测。为凑视觉维度而新增接口或推断字段，均违反 §3 全局约束。

## 6. 状态语义表与两层状态模型

**表 5 · T02 状态语义表**（解决 A7，不再悬置；T02 评审时确定色值；v1.2 补「数据来源」列与搜索通道）

| 维度 | 表达什么 | 视觉方式 | 数据来源（§5 表 4） | 与现有实现的关系 |
|---|---|---|---|---|
| 记忆新鲜度 | 多久没有被有效回顾 | 节点**亮度** | `/api/graph` 的 `nodes[].memory` | 沿用现有记忆档位表达，不被皮肤覆盖 |
| 搜索匹配程度 | 当前搜索命中与否 | 节点**透明度 / 饱和度** | 前端搜索结果，无后端字段 | **独立通道，不占用亮度** |
| 复习状态 | 是否到了应复习时间 | **橙色提示标记** | `/api/learning/today` 的 `reasonCode` / `nextReviewAt`（仅今日推荐条目） | 独立于亮度，不与记忆新鲜度共用通道 |
| 掌握证据 | 是否存在真实学习记录 | **青色外环** | `latestResult`（间接、非全图谱） | **无可靠字段时不显示**；不得称「已掌握」 |
| 选中状态 | 当前交互焦点 | 双层光环（交互态） | 交互状态，无数据字段 | **不是业务状态**，不与上述四者冲突 |

> **T09 视觉编码优先级**：亮度（记忆）→ 透明度（搜索）→ 外环（掌握证据）→ 提示标记（复习）→ 光环（交互选中）；同一节点可叠加表达。硬规则见 §4「视觉属性唯一语义表」：**搜索聚焦不得覆盖记忆亮度**。

**表 6 · T05 两层状态模型与转换图**（v1.2；**保留原六种产品状态名称，但不实现为一个互斥的状态枚举**）

六种产品状态并不属于同一层级。若强行互斥，搜索、选中、AI 上下文会相互覆盖。因此拆为两层：

**第一层 · 主交互模式（5 种，互斥）**

| 主模式 | 进入条件 | 退出条件 |
|---|---|---|
| 自由探索 | 默认 / 清除其它模式 | 转入任一其它主模式 |
| 搜索聚焦 | 输入关键词 | 清除搜索 / 点空白 |
| 路径探索 | 选择两个节点 | 清除路径 / 点空白 |
| 学习模式 | 从图谱进入学习舱 | 退出学习舱 |
| AI 探索 | 从选中节点唤起 AI | 关闭 AI 浮层 |

> 「节点选中」从主模式中移出，降为第二层的独立上下文；**名称保留**用于产品沟通，但不再与五种主模式互斥。

**第二层 · 独立交互上下文（5 项，不互斥、可并存）**

| 上下文 | 说明 |
|---|---|
| 当前选中节点 | 切换主模式后仍应保留 |
| 当前搜索词与结果 | 点击节点后不应消失 |
| 路径起点与终点 | 与选中节点可同时存在 |
| 浮层展开状态 | 详情 / AI 浮层独立于主模式 |
| 离开前的图谱位置 | 学习或 AI 返回时还原视角 |

**主模式转换表**（表格化，便于逐条验收；实际转换规则在 T05 评审时确认）

| 起始主模式 | 触发动作 | 目标主模式 | 对应实现任务 |
|---|---|---|---|
| 自由探索 | 输入关键词 | 搜索聚焦 | T12 |
| 搜索聚焦 | 点击命中结果 / 节点（**仅更新选中上下文**） | 仍为搜索聚焦 | T12、T13 |
| 搜索聚焦 / 自由探索 | 选择两个节点 | 路径探索 | T14 |
| 任一主模式 | 从节点唤起 AI | AI 探索 | T21 |
| 任一主模式 | 从图谱进入学习舱 | 学习模式 | T18、T19 |
| 学习模式 / AI 探索 | 退出 / 关闭 | 回到进入前主模式（**保留第二层上下文**） | T19、T21 |
| 任一状态 | 清除搜索 / 点空白 / 退出学习 / 关闭 AI | 回到上一主模式或自由探索 | T12、T13、T21 |

> **关键约束**：切换主模式时第二层上下文必须保留，不得因互斥而清空。搜索已聚焦后点击节点，搜索上下文不应消失；选中节点后打开 AI 浮层，选中节点仍应存在。T05 的状态转换图与 T14 的状态编排规则均按此两层模型验收。
