二、核心模块及依赖关系
1. 请求链路
浏览器页面
  ↓ src/lib/client.ts（统一 fetch + 错误转换）
  ↓ src/proxy.ts（Cookie 会话校验；页面跳 /login，API 返回 401）
  ↓ API Route 内的 guard()（二次校验）
  ↓ Drizzle ORM
  ↓ Neon HTTP
  ↘ Cloudflare R2（原始 Markdown）
  ↘ DeepSeek API（AI 拆解/聚合/问答/摘要）
2. 数据库模型
当前 schema 包含 8 张表：

表	关系与用途
documents	文档；1:N segments
segments	知识点；含 stability、readingMs、summary 等阅读观测字段
links	知识点自关联；wiki / tag / doc 三类边；unique(from,to,kind)
annotations	划线与笔记；N:1 segments；锚点四元组 quote/occurrence/prefix/suffix
reading_events	有效阅读流水；N:1 segments
app_settings	键值设置；llm 存 API Key/model，learner 存学习者自述
llm_cache	LLM preview 输出缓存，上限 256 条
llm_calls	LLM 调用可观测流水，只记维度/用量/耗时/错误摘要
迁移为 0000–0006。注意：0000_init 里仍包含旧 SM-2 字段和 review_logs，0001 新增记忆曲线字段，0002 再删除旧字段和旧表。新库从 0000 顺序执行是完整的，但老库重复全量执行会出问题，见问题清单。

3. 主要业务流程
导入
/import → POST /api/notes → splitMarkdown() 解析 frontmatter、标题层级、超长段落 → 可选 semanticSplit() 调 LLM → putOriginal() 备份 R2 → 写 documents/segments → buildLinks() 建 doc/wiki/tag 边 → 失效 graph/stats/docs 缓存。

阅读与记忆
/segments/[id] → POST /api/segments/[id]/view：

打开 ping：viewCount + 1、补 firstViewedAt
页面隐藏/卸载：sendBeacon 上报停留时长
≥5 秒才写 reading_events，按 lib/memory.ts 推进 stability、累计 readingMs、刷新 lastViewedAt
记忆度 M(t)=exp(-Δt/S) 在 API 读取时现算，不落库。
概览
/ → /api/stats → SQL 聚合档位分布、今日阅读、最近导入、薄弱 Top3、未读 Top3 → DashboardPanel。

关系图谱
/graph → /api/graph → 全量 segments + links → 前端按记忆档位/关联类型过滤 → react-force-graph-2d 绘制；支持 ?fixture=graph-small|mid|large 压测数据。

AI 编辑
/ask 或 /notes/[id] 编辑态 → /api/ai/split-preview|aggregate-preview|ask → llm.ts + rag.ts + learner-profile.ts + llm-cache.ts → 生成预览 → 用户确认 → /api/ai/split-apply|aggregate-apply 写库并重建边、迁移标注。

标注
/notes/[id] 选区 → lib/annotations.ts 计算锚点 → POST /api/segments/[id]/annotations → lib/highlight.ts 在渲染文本上注入 <mark>；内容编辑后按“精确 → 上下文模糊 → 失效”三级重定位。

P3：低优先级技术债

登录无速率限制，口令比较使用普通 !==，存在暴力尝试/时序侧信道风险（个人自用场景影响有限）。
LLM API Key 明文存 app_settings，GET/接口只回尾 4 位，但数据库泄露时密钥可直接使用；无加密/KMS。
无 CSP、X-Frame-Options 等安全响应头；图谱 XSS 的利用面因此更大。
view 接口接受任意 durationMs，reading_events.duration_ms 存原始值，startedAt 可被推到任意过去；readingMs 虽封顶 10 分钟，但事件流水可被污染。
POST /api/notes/[id]/segments 的 afterIndex 只做 Math.min/max，字符串或 NaN 会进入 SQL 参数，可能 500。
extractInlineTags() 不跳过代码围栏，代码块里的 #tag 会被当作标签。
notes/[id] 前端 DocDetail.segments 类型声明了 summary，但 /api/notes/[id] 实际不返回该字段；当前未使用，属于类型漂移。
llm_cache 过期行在 getCachedOutput 返回 null 后，saveCachedOutput 使用 onConflictDoNothing，不会刷新过期行；当前 split/aggregate 未设置过期时间，属于潜伏问题。
chatCompletionStream 用 60 秒 AbortSignal.timeout 覆盖整个流式读取，长回答可能被中途截断。
isRetryableError 对没有 status 的本地解析错误也返回 true，会对“输出截断/JSON 不合法”这类确定性错误重试一次，浪费 token。
vitest.config.ts 是 ESM 语法但被当作 CJS 加载，Vitest 已给出未来 Vite 兼容性警告。
云端知识库 镜像目录会让 tsc/ESLint 重复扫描；ESLint 从根目录检查 92 个文件，包含镜像副本，建议加入 ignore 或清理。
README 未说明迁移 --only 的正确用法；docs/llm-optimization-plan.md 也明确写了“全量重放会卡死”的已知陷阱。
4.2 代码路径已定位、但需要运行时复现的风险
这些不是凭空猜测，而是已在代码中定位、尚未在真实环境验证影响程度：

迁移重放失败：静态确认 SQL 错误码路径；需要在 staging Neon 上实际执行一次全量重放验证。
标注偏移：需要浏览器中制造“摘要加载/本节笔记数量变化 + 已有划线”场景，确认 <mark> 是否错位。
AI 应用后的编辑卡旧状态：需要在浏览器执行拆解/聚合，确认 SectionEditor 是否仍显示旧内容。
LLM 信号量超限：需要并发 10 个 preview/ask 请求并打印实际并发数，确认是否超过 3。
流式槽泄漏：需要模拟客户端断连或上游中途断流，观察后续请求是否被阻塞。
图谱性能阈值：需要用 ?fixture=graph-mid|graph-large 在目标设备上跑首帧、帧率、长任务；fixtures 当前被 .gitignore 忽略，需要先生成。
DeepSeek 模型/function calling：src/app/api/ai/ask/route.ts 注释明确写了“deepseek-v4-flash 的 function calling 未实测”；当前无 API Key，无法验证真实模型 id 和 tools 支持。
R2 失败/孤儿对象：导入先 putOriginal 再写 DB；需要模拟 R2 成功、DB 失败，确认是否留下无引用对象。
Vercel 多实例缓存：lib/cache.ts 是进程内 TTL 缓存，多实例下写后失效只影响当前实例；需要部署环境验证 stale 窗口。
数据库备份/恢复：仓库没有备份脚本或恢复演练记录；这是运维假设，不是代码缺陷。

建议执行顺序
先做 P1-1 安全加固：XSS、鉴权 fail-open、开放重定向都是低改动、高收益。
再做 P1-2 迁移与原子性：这是部署和数据安全的底座，且会决定后续 AI apply 的可靠性。
然后 P1-3 阅读闭环：这是产品核心价值，越早补齐越能验证记忆模型。
随后 P2-1/P2-2 一致性：标注、编辑态、缓存都属于同一批“读写后 UI 不一致”问题。
最后 P2-3/P2-4：LLM 成本/可靠性与图谱规模、CI、文档可以并行推进。
六、结论与等待确认
项目整体健康度：中上。 代码分层清楚，README 与主要业务链路完整，纯函数模块测试质量不错；npm test、npm run lint、npx tsc --noEmit、npm run build 全部通过，Git 工作区干净。

但目前存在几个不能忽视的点：

安全面：图谱 tooltip 的存储型 XSS、未配置口令时的鉴权绕过、登录开放重定向；
数据面：迁移脚本不可安全重放、多步写操作无原子性、标注/缓存/摘要存在一致性缺口；
产品面：整篇连续阅读不计阅读行为，核心记忆闭环只覆盖单知识点页；
工程面：关键路由缺少测试、没有 CI、docs/spec.md 与当前 schema 漂移。
